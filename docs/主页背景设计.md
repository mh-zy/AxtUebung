# 主页背景导入与染色设计

最后更新：2026-10-21

范围：只在首页显示背景，不进入刷题、结果、设置等页面。

当前状态：已在 0.3.0 实现导入、自动染色、原彩、透明度、铺放方式和三段覆盖。

实现补充：

* Android 返回手势与本功能无关，但 0.3.0 同时加入了返回事件双层消抖；
* 首页标题整体下移约 6px，背景顶部边界跟随新标题高度。

## 目标

1. 支持从本地导入 PNG/JPEG/BMP 作为首页背景。
2. 灰度或透明线条图可以用当前主题强调色染色。
3. 彩色图片保持原色，但允许降低不透明度以保护文字可读性。
4. Windows 与 Android 使用同一套图片、纹理缓存和设置格式。

## 推荐的用户接口

设置 → 界面 → 首页背景：

| 控件 | 选项 |
| --- | --- |
| 背景 | 无 / Doppelaxt / Hellebarde / 导入图片 |
| 模式 | 自动 / 主题染色 / 原彩 |
| 不透明度 | 0~100%，默认 22% |
| 铺放 | 覆盖 / 完整显示，默认覆盖 |
| 操作 | 导入、替换、移除 |

“自动”规则：只统计 alpha > 0 的像素；若平均饱和度很低，则按灰度图染色，否则按原彩显示。仍允许用户手动覆盖自动判断。

## 文件与设置

内置背景：

```text
assets/background/Doppelaxt.png
assets/background/Hellebarde.png
```

用户导入背景复制到：

```text
<数据目录>/background/home-<内容哈希>.png
```

不要把 SAF 临时 URI 或绝对路径写进设置。建议在 `settings.txt` 使用：

```ini
home_background_source = none|asset:Doppelaxt.png|user:home-abc123.png
home_background_mode = auto|tint|color
home_background_opacity = 0.22
home_background_fit = cover|contain
```

替换背景时先成功解码新图，再删除旧用户图片。路径只允许图片目录内的文件名，拒绝 `..`、绝对路径和 URL。

## 解码与纹理

当前软件渲染器只有 SVG 图标纹理，没有普通位图解码。建议复用 `docs/图片支持设计.md` 中已经评估过的路线：

1. 平台层新增二进制读取接口 `readBinaryFile` / `readAssetBinary`。
2. 引入单头文件 `stb_image.h`，支持 PNG/JPEG/BMP；它只负责解码，不需要平台各写一套。
3. 解码后最长边限制在 2048px；超过时等比缩小，避免一张手机照片长期占用几十 MB。
4. 复用 `ImGuiRenderer` 的内部纹理表注册 RGBA 纹理。
5. 缓存键包含：文件路径、修改时间/大小、有效模式、染色颜色。

### 原彩接口

原色纹理直接保留 RGB 和 alpha，绘制时只应用整体不透明度：

```text
output.rgb = source.rgb
output.a   = source.a * opacity
```

在图片上方再叠一层主题窗口底色半透明遮罩，保证卡片和文字区域仍有足够对比度。

### 灰度染色接口

透明像素保持透明，非透明像素按亮度映射到主题色：

```text
gray = Rec.709(source.rgb)
rgb  = mix(themeBackground, themeAccent, 0.30 + 0.70 * gray)
alpha = source.alpha * opacity
```

这样黑色线稿仍有阴影层次，白色高光会接近强调色，而不是整张图变成单一纯色。

模式确定为灰度染色时，主题强调色或背景色变化后重生成纹理；原彩纹理无需随主题重建。

## 绘制顺序

首页只使用以下顺序：

1. 主题窗口底色；
2. 背景图片，按 `cover` 居中裁剪或按 `contain` 留空；
3. 主题色半透明遮罩；
4. 标题、题库卡片、模式栏、导出栏等正常 UI。

背景图只参与首页主窗口的背景层，不覆盖弹窗和页面卡片。卡片继续保持现有不透明底色，避免图片干扰文字。

## 导入流程

Android：

1. 使用现有 Storage Access Framework 选择单张图片；
2. 读取并解码，确认格式和尺寸有效；
3. 复制到应用私有 `files/background/`；
4. 保存相对文件名和显示选项。

Windows：

1. 使用现有系统打开文件对话框；
2. 同样先解码验证，再复制到 `data/background/`；
3. 保存设置并触发纹理重建。

失败时保留原背景，并提示“图片无法解码”或“文件过大”，不要先删除旧图。

## 约束与风险

* 不引入 WebP：`stb_image` 默认不支持，第一版只承诺 PNG/JPEG/BMP。
* 不把背景写入题库文件，也不影响题库导入导出。
* 背景只作用于首页，避免刷题时影响阅读。
* 彩色图默认低不透明度，不提供自动抠图或智能去背景。
* 需要在 `THIRD_PARTY_NOTICES.md` 中补充 `stb_image` 来源和许可。
