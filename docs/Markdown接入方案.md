# 使用手册 Markdown 接入方案

最后更新：2026-10-24

## 当前实现

1.0.0-alpha 使用轻量 Markdown 子集，文件位于：

```text
assets/manual/<page>.<language>.md
```

当前支持：

* `#` 一级标题；
* `##` 二级标题；
* `- ` 无序列表；
* `- @icon:file.svg 说明` 本地 SVG 图标行（按主题图标色渲染）；
* `---` 分隔线；
* 普通段落、空行；
* 中文缺失时自动回退 `zh-CN`。

渲染直接生成 ImGui 文本控件，不依赖 WebView，也不新增 Markdown 第三方库。

## 为什么先不用完整解析器

完整 Markdown 涉及嵌套列表、表格、链接、图片、代码块、引用、HTML 和行内样式。当前软件渲染器没有完整的富文本排版层，直接引入解析器后仍需要把 AST 转成 ImGui 绘制指令。

因此第一版先保证：

* 文本可维护、可 diff；
* 内容文件已经按 Markdown 组织；
* 后续替换渲染器时不需要重写手册正文。

## 后续接入路线

### 方案 A：扩展当前子集（推荐近期）

增加：

* `1.` 有序列表；
* `> ` 引用；
* 行内 `code`；
* `**粗体**`；
* 本地图片 `![说明](images/name.png)`。

图片继续通过 `render::loadBackgroundTexture` 同类位图加载路径注册纹理。优点是体积小、两端行为一致。

### 方案 B：引入成熟 Markdown 解析器

候选为 md4c 一类 C/C++ 解析器。解析器只负责生成 AST 或事件流，ImGui 侧仍需实现：

* 段落和标题排版；
* 列表缩进；
* 行内样式 span；
* 本地图片尺寸和缓存；
* 链接点击。

适合手册需要表格、代码块和复杂嵌套之后再做。

### 方案 C：HTML / WebView

不推荐作为主方案：

* Android 与 Windows 需要两套渲染容器；
* 与现有纯 C++ 事件驱动界面割裂；
* 需要处理 HTML 安全、字体和主题同步。

可作为以后打开外部帮助网页的独立入口，而不是应用内手册主渲染器。

## 文件与安全约束

* 手册只读取 `assets/manual/` 或未来数据目录中的白名单 Markdown 文件；
* 不允许网络图片和远程链接自动加载；
* 本地图片只能引用 `assets/manual/images/` 内相对路径；
* 原始 HTML 默认按纯文本显示；
* 用户自定义手册若开放，必须校验 `..`、绝对路径和可执行协议。

## 推荐顺序

1. 0.4.0：标题、列表、段落、分隔线（已完成）；
2. 加入有序列表、引用和本地图片；
3. 导入/导出图解目前不显示在手册目录中；以后恢复入口时再使用 Markdown 图片语法；
4. 手册复杂到需要表格或代码块时，再评估 md4c。
