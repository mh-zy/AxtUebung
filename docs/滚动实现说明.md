# 滚动实现与文件清单（0.2.0）

本文记录当前版本“在页面内任意位置拖动滚动”的完整链路。滚动由四层配合：

```text
Android 触摸
  → ImGuiRenderer 的 DOWN / MOVE / UP 排序队列
  → UiScroll 的手势状态机
  → 具体 BeginChild 窗口的 ScrollY
```

## 文件清单

| 文件 | 作用 |
| --- | --- |
| `ui/include/quiz/ui/UiScroll.h` | 手势状态机、控件起手仲裁、`ClearActiveID()`、惯性速度与衰减 |
| `ui/src/UiApp.cpp` | `bank_list`、题型总览、材料卷面、错题本、统计页、标签导出、考试成绩列表；`cardBegin/cardEnd` 的局部滚动 |
| `ui/src/SettingsScreen.cpp` | 设置 → 提示词的 `prompt_preview` 滚动区 |
| `render/include/quiz/render/ImGuiRenderer.h` | 指针事件序号；保证移动事件不会越过对应的按下 / 抬起边沿 |
| `render/src/ImGuiRenderer.cpp` | DOWN / MOVE / UP 的排序发送；每帧最多一个边沿，但松手前的最终 MOVE 必须先送达 |
| `platform/android/AndroidMain.cpp` | Android 单指事件、`touchScale` 坐标换算；惯性期间保持 `active` 呈现 |
| `platform/windows/WinMain.cpp` | Windows 同样的惯性重绘接入 |

## 手势状态

| 状态 | 条件 | 行为 |
| --- | --- | --- |
| `Pending` | 刚按下，位移不足 | 不滚动，不取消控件 |
| `Scroll` | 纵向 ≥ 8px 且 `\|dy\| > \|dx\| × 1.15` | 取消控件 `ActiveId`，进入滚动 |
| `Control` | 横向 ≥ 12px，或从原生滚动条起手 | 控件优先直到松手 |
| `Coasting` | 松手速度 ≥ 120px/s | 按速度继续滚动并衰减 |
| `Idle` | 已松开或动画结束 | 等待下一次按下 |

关键点：

- 按下时不裁决“控件赢”，只有明显纵向移动后才接管。
- 按钮 / 输入框拿到 `ActiveId` 后，ImGui 的 `IsWindowHovered()` 默认返回 false；
  滚动目标用 `HoveredWindow` 层级判断，而不是 `IsWindowHovered()`。
- 纵向接管时调用一次 `ImGui::ClearActiveID()`，因此松手不会触发按钮，
  也不会继续拖动输入框选区。输入框失焦后 Android 软键盘会收起。
- 横向动作保留给输入框选字、滑条、颜色控件等。
- 原生滚动条通过 `GetWindowScrollbarID()` 排除，不抢其拖动。
- 内层卡片能滚动时捕获内层；内容不足时目标自动落到外层列表。

## 输入边沿顺序

Android 一次 poll 可能同时收到 DOWN、若干 MOVE、UP。若按“每帧一个边沿”
简单节流，会出现 DOWN 帧丢掉 MOVE、下一帧直接 UP，ImGui 只看到原地点击。

因此 `PointerEvent` 带全局序号，待处理 MOVE 只有在序号早于队首边沿时先发送：

```text
DOWN → MOVE(最终位置) → UP
```

移动仍只保留最新位置，不会积压；代价是拖动松手可能多一帧，但不会丢手势。

## 惯性参数

- 速度使用最近约 60ms 的位移低通估算；
- 松手前超过 80ms 没移动，不启动惯性；
- 启动阈值 120px/s，最大 3500px/s；
- 每帧 `v *= exp(-6 × dt)`；
- `|v| < 30px/s` 或到达上下边界时停止；
- 新按下立即终止惯性；
- 平台主循环通过 `isScrollAnimationActive()` 在 0.4 秒输入重绘窗口之外继续保持呈现。

## Android 0.2.0 验证

在 Android 模拟器上实测：

- 从题库卡片按钮内部上滑：日志确认 `起手控件=1`、`active≠0`，随后滚动并进入惯性；
- 惯性日志：以 288px/s 启动，松手后继续 45px，降至 28px/s 停止；
- 同位置短按仍能正常打开题库；
- 快速滑动时 MOVE 在 UP 前送达，不再误判成原地点击。
