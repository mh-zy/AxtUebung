# 考试模式设计稿（已落地 —— 留作设计记录）

> **状态：0.0.2 已实现**（2026-10-16，Windows 无头截图实测；Android 只编译）。
> 用户拍板的 6 点就是下面第 6 节里推荐的那套：卷声明放题库文件、材料规则 count 数「几段材料」、
> 允许中途改答案、按分值算分、交卷那一刻才写进度、卷内按难度排列。
> 实际用法见 `docs/题库格式.md` 第七节；实现与本文的差异：shuffle = 1 时按种子打乱
> （以「一段材料」为单位），空题**不写进度**（不算错题，只在成绩里 0 分）。

> 现状：题型、判分、材料题卷面、错题本、抽题（权重刷题）都有了；**缺的是「整卷」这一层** ——
> 现在没有整卷计时、及格线、卷面分值，也没有「按规则抽题生成一套模拟卷」的能力。
> 下面这份是把题库格式和会话两层怎么改想清楚，**动手前请先确认第 6 节的几个选择**。

## 1. 一句话设计

题库文件里**新增两个可选段**：`[exam]`（一套卷的定义：时长、及格线、随机种子）+
`[draw]`（一条抽题规则：抽几道、什么题型/难度/标签、每题几分，可写多条）；运行时由一个
`ExamBuilder` 按规则 + 种子从题库里**可复现地**抽出题号列表，直接喂给现有的 `session.setOrder()`；
会话新增「考试模式」——答题期间只记草稿**不判分不写进度**，交卷时统一判分（错题照旧进错题本）。

## 2. 题库格式扩展（都放在题库文件里）

为什么放题库文件里：和 `[material]` 一个路子，题库自己描述「我适合怎么出卷」；单文件就能分享，
不用再发明一种"试卷文件 + 引用题库"的跨文件格式。跨题库组卷以后要做，再加 `assets/exams/*.txt`。

### 2.1 `[exam]`：一套卷

```ini
[exam]
id = mock-a                  # 可选；用于进度/导出命名，缺省用 title 或序号
title = 期中模拟卷 A           # 显示名（必填）
minutes = 60                 # 限时（分钟）；不写 = 不限时
pass = 60                    # 及格线（百分比）；不写 = 不判及格
seed = 2026                  # 抽题种子；写了就每次抽到同一套题（模拟卷要可复现），不写 = 每次重抽
shuffle = 1                  # 卷内题序是否打乱（默认 0 = 按规则顺序）
desc = 覆盖第一章到第三章       # 说明（可选）
```

> 可以写多个 `[exam]` 段 → 一个题库带好几套卷（A 卷 / B 卷 / 真题卷…），入口里让用户选。

### 2.2 `[draw]`：一条抽题规则（在它所属的 `[exam]` 之后写，几条就按顺序拼成卷）

```ini
[draw]
count = 10                   # 题数（type = material 时表示「几段材料」，见 2.3）
type = single,multiple       # 题型，逗号分隔可多选；不写 = 不限
difficulty = 2-5             # 难度区间（1~5）；不写 = 不限
tags = 第一章,第二章           # 标签，命中任意一个即可（或的关系）；不写 = 不限
exclude_tags = 送分题          # 命中就排除（可选）
material = any               # only/material-id：只抽材料题（any）/ 指定某段材料 m1
id = q3,q7                   # 点名抽（必考/调试用）；写了就不随机
score = 2                    # 这条规则抽到的每题分值（默认 1）
```

### 2.3 材料题怎么抽

材料题必须**整段连抽**（一段材料的几道小题在同一页作答，拆开没意义）：

- `type = material` 时，`count` 解释为**几段材料**（不是几道小题）；每段的全部小题按 `materialPart` 顺序进卷。
- 其它规则命中材料小题时，也把它整段一起带进来（并在 issues 里提示"为材料段补齐了 N 道小题"）。

### 2.4 `[q]` 新增一个键

| 键 | 说明 |
| --- | --- |
| `score` | 这道题的分值（默认 1）。`[draw]` 里的 `score` 会覆盖它 |

卷面总分 = 卷内各题分值之和；判分沿用现有 0~1 得分 × 分值（部分分按比例给分）。

## 3. 抽题算法（ExamBuilder）

1. 按 `[draw]` 顺序处理；每条规则先按 type / difficulty / tags / material / id 过滤出候选池。
2. 候选池用 `mt19937(seed)` 洗一遍（种子相同 → 结果相同），按顺序取，`count` 取满为止。
3. **跨规则不重复**：一个全局 `used` 集合，已经进卷的题目（或材料段）不再被后面的规则抽到。
4. 材料段按「段」为单位参与洗牌与取用。
5. 抽不满（题库不够 / 过滤太严）：把能抽的都放进卷，并在 `issues` 里报
   `第 N 条抽题规则只抽到 x/y`（导入时就能看见，不静默少题）。
6. 输出 `std::vector<int> questionIndexes`（原始题号，按卷面顺序）。

## 4. 会话与界面怎么改

- `QuizSession` 新增 `examMode_`（和现有 `reciteMode_` / `wrongOnlyRound_` 一个做法）：
  - 答题期间 `submit()` 只记「已作答」+ 草稿，**不判分、不写进度、不喂累计统计**（选择题可以随时改答案）；
  - `finishExam()`：逐题按草稿判分写进度 → 错题照旧进错题本、累计统计照旧 +1；
  - UI 在 exam 模式下不画判定卡（不显示对错/解析），只显示"已作答/未作答"。
- 倒计时：`AppContext` 记截止时间（用 `monotonicSeconds`），界面顶部显示剩余（最后 5 分钟变红），到点自动交卷。
- 交卷后 → 成绩页：得分/满分、正确率、及格与否、逐题对错列表（"重做错题/导出错题本"沿用现有按钮）。
- 首页「考试」按钮不再灰：题库里有 `[exam]` 就列出卷名让用户选；没有就提示"这个题库没有出卷规则"。
- 导出（`saveBank`）保留 `[exam]`/`[draw]`/`score`，别把组卷能力丢了。

## 5. 落地步骤（建议按这个顺序，每步都能单独验）

1. 解析：`[exam]` / `[draw]` / `[q] score` → 模型 + 单测（坏值只报 issue 不影响其它段）。
2. `ExamBuilder`：种子可复现、跨规则不重复、材料整段、抽不满报 issue → 单测。
3. 会话：`examMode_` + `finishExam()` → 单测（草稿不落盘、交卷才写进度、错题进本）。
4. 界面：选卷入口 + 倒计时 + 交卷 + 成绩页。
5. 文档：`docs/题库格式.md` 补 `[exam]`/`[draw]`/`score` 章节；顺手把"现在还没有的"里
   那条"没有整卷计时、及格线这类考试模式"改掉。
6. 顺带：命令行 `--paper <卷id>`（把抽题结果打印出来，便于校验和排错）。

## 6. 动手前要你拍板的几点

1. 卷定义**放题库文件里**（本稿推荐）还是单独一种试卷文件？
2. 材料规则里 `count` 算「几段材料」（本稿推荐）还是「几道小题」？
3. 考试中**允许改答案**（草稿制，本稿推荐）还是每题答完就锁死？
4. 分值：题目自带 `score` + 规则可覆盖（本稿推荐）？还是干脆不要分值、只按题数算正确率？
5. 交卷那一刻才把结果写进进度（错题进本+累计统计，本稿推荐）—— 确认无误？
6. 卷内默认**不打乱**（按 `[draw]` 顺序）还是默认打乱？
