# 题目数学公式兼容方案

最后更新：2026-10-23

## 当前状态

0.4.0 已实现第一层和第二层：

* `$...$` 行内公式与 `$$...$$` 独立公式块会在显示层拆分；
* 常见 LaTeX 命令转换为 Unicode 后参与实际字体宽度测量和自动换行；
* 独立公式块单独居中，超宽时仍按卡片可用宽度换行；
* 题干、选项、有序题备选池、材料正文、材料小题、解析、标准答案、错题列表和考试回看使用同一套显示入口；
* 未闭合的 `$`、无法映射的上下标和未知命令原样保留，文本不能被截断；
* 题库文件、题库导出和进度数据继续保存原始 LaTeX，不做有损转换。

第一层实现位于 `core/src/text/MathText.cpp`，第二层的 UI 排版适配位于
`ui/src/UiApp.cpp`。核心解析不依赖 ImGui，可以直接运行单元测试。

## 现状与限制

完整公式排版尚未实现。当前兼容层把公式当作“转换为 Unicode 的文本片段”显示，
不会真正排布分式上下结构、根号顶线、矩阵或大型运算符，例如：

```text
$\frac{1}{2}$
$x^2 + y^2 = r^2$
$\sqrt{a+b}$
```

这些公式在 0.4.0 中会显示成 `1/2`、`x² + y² = r²`、`√(a+b)`；
视觉上可读，但不等于完整数学排版。

## 推荐路线

### 第一层：Unicode 兼容（0.4.0 已实现）

对简单公式做无依赖转换：

* `^2` → `²`；
* `_1` → `₁`；
* `\alpha`、`\beta`、`\pi` → `α`、`β`、`π`；
* `\le`、`\ge`、`\ne`、`\times`、`\div` → 对应数学符号；
* 简单分数转换成 `分子/分母` 形式。

这一层可以立即兼容一部分基础题目，并保留原始 LaTeX 文本，不修改题库文件。

### 第二层：公式片段解析（0.4.0 已实现）

定义：

* `$...$` 为行内公式；
* `$$...$$` 为独立公式块。

文本排版器把一行拆成“普通文字 / 公式”片段。普通文字和转换后的公式字形都使用实际字体宽度测量，
超过可用宽度时换行。题库原字段不拆分、不改写，导出时仍保留原公式。

实现说明：

* `MathSegment` 同时保存原始公式 `source` 和当前显示文本 `text`；
* 行内公式与相邻普通文字合并为同一文本流，按真实字形宽度换行；
* 独立公式块在垂直方向增加间距并按卡片宽度居中；
* 卡片高度、选项高度和实际绘制共用同一测量函数，避免公式换行后出现裁切或多余滚动条。

### 第三层：完整公式渲染（后续版本计划）

复杂公式建议渲染为可缓存的纹理，再作为公式片段插入文字流：

```text
LaTeX → AST → 布局框 → 纹理或矢量图元 → ImGui
```

候选实现：

1. **MicroTeX 一类本地 C++ 渲染器**：跨端一致，适合软件光栅化；需要评估许可证、CJK 字体和输出接口。
2. **KaTeX/MathJax 预渲染**：作者工具链预生成 SVG/PNG；显示效果成熟，但需要把图片随题库携带。
3. **WebView + KaTeX**：渲染完整，但与当前纯 C++ UI 割裂，Android/Windows 双端成本高，不作为主路线。

### 第三层实施计划

1. **确定渲染后端**
   * 优先评估 MicroTeX：核对许可证、Android NDK/Windows MSVC 构建方式、字体嵌入和纹理输出接口。
   * 若本地 C++ 后端维护成本过高，改为作者工具预渲染公式，题库携带结果图或缓存包。
   * WebView 只作为外部帮助页的备选，不进入题库主渲染路径。
2. **保留当前解析边界**
   * 继续使用 `MathSegment::source` 作为缓存键，不改变 `$` / `$$` 语法。
   * 第一、二层继续作为渲染失败时的回退，不让复杂公式导致整段文字消失。
3. **建立公式布局接口**
   * 输入：原始 LaTeX、字号、DPI、主题文字色、公式类型。
   * 输出：位图或矢量纹理、基线偏移、宽高、错误状态。
   * 行内公式按基线对齐；独立公式按块居中。
4. **接入统一文字排版**
   * 让 `mathTextRuns()` 从“Unicode 文本段”升级为“文本段 / 公式纹理段”。
   * 换行测量从 `CalcTextSize()` 改为文本宽度 + 公式宽度的组合测量。
   * 题干、选项、材料、解析和标准答案继续复用同一接口，禁止按页面分别实现。
5. **缓存与失效**
   * 缓存键至少包含规范化 LaTeX、字号、字体、主题文字色和 DPI。
   * 对高频公式做 LRU 内存缓存，磁盘缓存仅在确认 Android 存储与 SAF 导出路径都稳定后启用。
   * 主题切换只重建与颜色相关的纹理。
6. **验证门槛**
   * 至少覆盖分式嵌套、根号、上下标组合、矩阵、求和/积分、化学式和长公式换行。
   * Windows 与 Android 使用同一题库回归题干、选项、材料、解析和考试模式。
   * 渲染失败必须回退到第二层 Unicode，不能崩溃或吞字。
7. **版本边界**
   * 第三层不随 0.4.0 发布。
   * 后端选型和第三方许可证确认后，再单独提升版本并更新第三方依赖清单。

## 纹理与缓存

公式纹理缓存的键至少包含：

```text
规范化后的 LaTeX + 字号 + 字体 + 主题文字色 + DPI
```

主题切换时只需要重建与颜色相关的公式纹理。公式渲染失败时显示原始 LaTeX 文本，不应让题目或页面崩溃。

## 排版要求

* 行内公式基线与相邻文字对齐；
* 分式、根号、上下标不被行高裁切；
* 公式宽度参与卡片换行，而不是按字符数估算；
* 独立公式块可以居中显示；
* 解析、选项和材料题复用同一套公式片段渲染；
* 考试、背题、错题回看显示一致。

## 推荐实现顺序

1. 验证题库中 LaTeX 的实际写法，统计常用命令；
2. 实现 Unicode 兼容和原始公式回退；
3. 引入公式片段解析和统一排版接口；
4. 选择本地 C++ 渲染器或离线预渲染，接入纹理缓存；
5. 最后再考虑完整行内公式和复杂矩阵、化学式等扩展。
