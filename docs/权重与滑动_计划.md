## A. 权重算法：引入标签与难度（**已实现，2026-10-18**）

> 实现结果：`weightedWeight()` 已按本文公式乘入难度与最弱标签因子；统计实时扫描，
> 提交后下一次补题立即使用新次数。无标签、无难度的题保持旧公式。Windows 核心单测覆盖
> 标签、难度、用户标签与即时刷新。滚动相关实现与文件清单见 `docs/滚动实现说明.md`。

### A.0 现状

`weightedWeight(i) = 0.15 + (1 - masteryAt(i))`，`masteryAt` 只看对错次数；
`Question::tags` / `Question::difficulty` 完全没进权重。

### A.1 目标

1. **弱项标签**的题多出；
2. **难度适配**：偏向「当前水平附近、略高一点」的题，太简单/太难都降权；
3. 仍然可复现（seed 决定）、可解释（三个因子相乘）、不改题库/进度格式；
4. 没有标签或难度的题库，效果与现在一致（向后兼容）。

### A.2 需要先聚合的统计量（抽题前重建，O(题数×标签数)）

| 统计 | 来源 | 说明 |
| --- | --- | --- |
| 每题 mastery | 已有 | right/wrong 次数 |
| 每标签 tagAsked / tagRight | 进度 + 题目标签 | `tagMastery = (tagRight + 1.5) / (tagAsked + 3)`（小样本往 0.5 收缩） |
| 每难度 diffAsked / diffRight | 进度 + 题目难度 | 样本 < 3 时用先验 `0.9 - 0.15×(d-1)`（d=1→0.9，d=5→0.3） |

实现：`QuizSession` 里加 `rebuildWeightStats()`；提交时置脏，下一次抽题前重建一次（几百道题足够快，不需要缓存）。

### A.3 公式（三个因子相乘）

1. **掌握度因子**（保留现状）：`fMastery = 0.15 + (1 - mastery)` → `[0.15, 1.15]`
2. **难度因子**：先估答对概率 `p`
   - 有作答记录：`p = 0.25 + 0.65 × mastery`
   - 没作答：`p = diffAccuracy[d]`（没写难度 → 0.65，不给偏好）
   然后 `fDiff = clamp(0.45 + 1.15 × (1 - |p - 0.65| / 0.65), 0.5, 1.6)`
   → p≈0.65（有挑战但能做对）拿满 1.6；p≈0 或 1 只有 0.5。
3. **标签因子**：取这道题**最弱**的那个标签的 mastery
   `fTag = clamp(0.55 + 1.05 × (1 - tagMastery), 0.55, 1.6)`；没有标签 = 1.0。
   用户自己加的标签同样参与。
4. **合成**：`weight = clamp(fMastery × fDiff × fTag, 0.05, 4.0)`，直接喂给现有 `pickWeighted`（接口不变）。

### A.4 可调项

先只做成常量：`kTargetP = 0.65`、`kDiffWeight = 1.15`、`kTagWeight = 1.05`。
若要暴露给用户，再加「设置 → 答题 → 权重参考：难度 / 标签 / 掌握度」三个开关（默认全开）。
**建议第一版不暴露**，先观察一轮。

### A.5 测试计划

1. 无标签、无难度 → `weightedWeight` 与旧公式逐题一致（回归）；
2. 同 mastery：标签弱（0/2） vs 标签强（8/8）→ 前者权重 ≥ 1.5×；
3. 用户 1–2 级全对、4–5 级全错 → 4–5 级未做题的权重 > 1–2 级；
4. 同 seed + 同进度 → 同一抽取序列；
5. 500 题 / 20 标签：`rebuildWeightStats` < 1 ms；
6. 提交后立即影响下一次补题（已有单测覆盖次数更新，再加一条「答错后该题权重上升」）。

### A.6 排期

聚合 + 公式 + 单测 **1 天**；文档 0.25 天；加设置开关 +0.5 天。

## B. 滚动页面：在页面范围内按住拖动即可滚动（0.1.1 基础版；0.2.0 已加控件起手与惯性）

> 0.2.0 已把“按下时控件优先”改成方向裁决状态机：按钮 / 输入框上纵向拖动也会接管滚动，
> 并加入惯性。详细参数、输入边沿排序和文件清单见 `docs/滚动实现说明.md`。

### B.0 现状

8 个滚动区（都是 `BeginChild`）：
`bank_list`、`paper_scroll`、`overview_grid`、`wrong_list`、`stats_scroll`、`exam_list`、`tag_export_list`、`prompt_preview`。
手机上只能拖右侧那条细滚动条（很难点中），滚轮只有桌面有。

### B.1 目标

- 按住页面内容上下拖 → 整页滚；
- 单击仍然正常点按钮（不误判）；
- 桌面滚轮保持原样；
- 惯性作为第二阶段（可选）。

### B.2 做法

1. `UiApp.cpp` 加工具函数（BeginChild 后、EndChild 前调用）：

```cpp
// 拖动内容区就滚动；按在按钮/输入框上不抢
void dragScrollInsideChild() {
    ImGuiIO& io = ImGui::GetIO();
    if (!ImGui::IsWindowHovered(ImGuiHoveredFlags_ChildWindows)) return;
    if (!ImGui::IsMouseDragging(0)) return;
    if (ImGui::IsAnyItemActive()) return;          // 按住的是按钮/输入框：不滚
    if (io.MouseDragMaxDistanceSqr[0] < 36.0f) return;   // 位移 < 6px：当点击
    ImGui::SetScrollY(ImGui::GetScrollY() - io.MouseDelta.y);
}
```
2. 8 处 `BeginChild` 统一换成 `beginScrollChild(name, size, flags)`（内部 `BeginChild` + 注册；`EndChild` 前调 `dragScrollInsideChild()`），避免复制粘贴。
3. 细节：
   - 选项行/卡片是 `InvisibleButton` → 按在它们上面拖动不会滚（会变成按住按钮）。第二阶段可把「按住 + 纵向移动 > 6px」判为滚动并取消点击（`ClearActiveID` 或 `PressedOnRelease`）。
   - 输入框里拖动 = 选文字，不滚（正确）。
   - 嵌套弹窗（总览、导出面板）不跟着外层滚：靠 `IsWindowHovered(ChildWindows)` 判断当前窗口。
4. 验证：
   - 无头工具加 `--drag "x1,y1,x2,y2,ms"`（注入 DOWN → MOVE → UP）；
   - Windows + 安卓各验：材料卷面从中间上拖 200px（页面动）、结算页列表拖动、点选项仍能选中。

### B.3 排期

工具函数 + 8 处接入 **0.5 天**；`--drag` 注入 + 双端验证 0.25 天；惯性 +0.5 天（可选）。
