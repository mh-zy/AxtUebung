# 架构说明

## 一、分层

```
        ┌───────────────────────────────────────────────┐
        │ ui/       页面、弹窗与组件                      │  ← 只依赖 core 与 render
        │           首页 / 刷题 / 材料卷面 / 结果 /      │
        │           统计 / 设置 / 考试（Dear ImGui）     │
        └───────────────────┬───────────────────────────┘
                            │ 调用
        ┌───────────────────▼───────────────────────────┐
        │ core/     平台无关的业务核心                   │
        │  model/     题目、题库、进度                   │
        │  io/        固定格式题库的读写（唯一格式实现）  │
        │  session/   答题会话状态机（选择/判分/统计）    │
        │  progress/  进度序列化                         │
        │  i18n/      语言包接口                         │
        │  app/       把它们组装成 AppContext            │
        └───────────────────┬───────────────────────────┘
                            │ 需要“系统能力”时只调用
        ┌───────────────────▼───────────────────────────┐
        │ platform/ 平台层（很薄）                       │
        │  Platform.h  日志/时钟/文件/资源/字体路径/数据目录 │
        │  windows/    Win32 窗口 + GDI 贴图 + 鼠标键盘   │
        │  android/    NativeActivity + 触摸 + 内部存储   │
        └───────────────────────────────────────────────┘
                            ▲
        ┌───────────────────┴───────────────────────────┐
        │ render/   ImGui 的软件渲染后端                  │
        │           把 ImGui 的三角形画进 RGB32 像素缓冲   │
        └───────────────────────────────────────────────┘
```

**为什么要这样分？**

* 换平台只动 `platform/`；`ui/` 与 `core/` 一行都不用改（Windows 与 Android 现在就是这样共用的）；
* 换 UI 框架（例如以后换成 SDL + 自绘控件）只动 `ui/` 与 `render/`；
* 业务逻辑（判分、统计、进度、导出）全部可单元测试，不需要设备也不需要窗口。

## 二、一次“答题”的完整链路

```
手指点击选项按钮（Android 触摸 / Windows 鼠标）
        │
        ├─ platform：把触摸坐标换算成画面坐标 → render::addPointerEvent
        │
        ├─ render：把事件喂给 ImGui，ImGui 判断命中了哪个按钮
        │
        ├─ ui/QuizScreen：按钮被点击 → session.selectOption(i)
        │
        ├─ core/QuizSession：记录选择；点「提交」时判分并写入 BankProgress
        │
        ├─ core/AppContext::saveProgress()：把进度序列化成文本写进数据目录
        │
        └─ 下一帧：ui 读到新的会话状态 → 选项变绿/变红、显示解析
```

## 三、扩展点（预留接口在哪）

| 想做的事 | 改哪里 | 说明 |
| --- | --- | --- |
| 加一种题型（填空/排序） | `core/include/quiz/model/Question.h` 的 `QuestionType` + `BankFormat.cpp` 的解析与校验 + `ui` 里画选项的分支 | 其它层不用动 |
| 换题库存储（数据库/网络） | `core/include/quiz/io/BankFormat.h` 的实现 | `AppContext` 只调这几个函数 |
| 换进度存储 | `core/include/quiz/progress/ProgressStore.h` | 目前是纯文本，可换成 SQLite/JSON |
| 加语言 | 放一个 `assets/lang/xx.lang`（或数据目录 `lang/xx.lang`） | **不用改代码、不用重新编译** |
| 题目内容多语言 | 题库里写 `stem.en = ...` | 见 `docs/题库格式.md` |
| 加页面（例如设置页/统计页） | `ui/include/quiz/ui/UiApp.h` 的 `Screen` 枚举 + 新 draw 函数 | |
| 换渲染方式（OpenGL/Vulkan/SDL） | `render/` | 保持 `render::initialize/beginFrame/endFrameAndRender` 三个函数签名即可 |
| 换 UI 框架 | `ui/` | `core/` 不变 |

## 四、几个实现细节

### 1. 为什么不用 OpenGL

ImGui 官方后端都基于图形 API，但刷题应用是**事件驱动**的：没有交互时画面不变。
所以这里写了一个「软件渲染后端」，把 ImGui 的三角形直接画进 RGB32 像素缓冲：

* Windows 用 GDI 的 `StretchDIBits` 把缓冲贴到窗口；
* Android 用 `ANativeWindow_lock` 把缓冲写进窗口缓冲区；
* 静止时不重新光栅化（`kKeepRenderingSeconds` 之外的帧跳过光栅化），省电。

好处：Android 端**完全不需要 Java/Kotlin**，也不需要 EGL/GLES 代码。
以后要上 3D 或复杂动画，可以再换成 GL 后端，`core/` 与 `ui/` 不受影响。

### 2. 字体

ImGui 1.92 的字体图集是「运行时按需生成字形」的，所以：

* 直接用系统字体，不打包字体文件：
  Windows 用 `C:/Windows/Fonts/msyh.ttc` 等，Android 用 `/system/fonts/NotoSansCJK-*.ttc`；
* 用到哪个汉字就生成哪个，启动快、占用小；
* **不要在 `NewFrame()` 之后修改字体图集**（改语言时要重建字体），
  所以平台层的循环里是「先 `ui.applyFontRebuild()`，再 `render::beginFrame()`」。

### 3. 进度文件

每次提交答案、切换题库、退出应用时都会调用 `AppContext::saveProgress()`，
所以断电、切后台都不会丢进度。文件是纯文本，出问题可以直接看、直接改。

进度文件里**只记「历史结论」**：这道题答过没有、最后一次对不对、答对/答错各几次
（`right` / `wrong`）、什么时候答的、有没有收藏、用户自己加的标签（`tags`）。

用户**选了什么、填了什么不写盘** —— 它们只活在 `QuizSession` 的草稿里，退出题库或关掉
程序就释放。所以：

* 重新打开题库时，每道题都是干净的（错题不会带着上次那个错选项回来），
  选择题的选项、填空题的输入框都是空的；
* 进度文件里看不到任何作答内容，只看得到「对错与次数」；
* 代价是「回头看看上次选了什么」目前做不到（要看得在本次会话里，或从未退出题库）。

### 4. 题库文件的解析

`core/src/io/BankFormat.cpp` 是唯一的格式实现：

* 解析时记录**行号**，出错能精确定位；
* 未知键只警告不中断（方便发现 `analysls` 这类打字错误）；
* 致命错误（缺题干、答案越界等）会让题库标记为不可用，但仍然可以在界面上看到原因。

## 五、目录速查

```
QuizApp/
├─ core/        业务核心（模型 / 格式 / 会话 / 进度 / 语言包 / AppContext）
├─ ui/          页面（ImGui）
├─ render/      ImGui 软件渲染后端
├─ platform/    Windows / Android 平台层
├─ app/         Android 打包壳（Gradle + 清单）
├─ assets/      题库与语言包（两端共用）
├─ tests/       单元测试（75 项检查，`ctest` 或直接运行 exe）
├─ tools/       构建脚本
└─ docs/        题库格式与架构说明
```
